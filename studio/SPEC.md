## Responsibility

Studio 管理 OpenZilo 连接、原始手势采集和训练，以及远程录音、实时 PCM、本机 IMU 校准与签名固件升级。仅支持 manifest 固定的新版 SDK，不增加旧 SDK API 适配。设备功能按每次连接的能力发现结果开放，未知契约不绕过检查。

## Boundary

独立 `hmm-gesture` 推理包不依赖 SDK、BLE、Qt、Tk、PyAV 或加密库。默认界面为 PySide6（`qt/`），旧 Tk 界面保留，由 `launcher.py` 选择；两者遵守同一份契约，下文的“Tk”同样适用于 Qt 主线程。界面仅在主线程更新；BLE 与设备操作在单独 asyncio worker 中运行，文件转换不占用界面/BLE 线程。应用层不复制 SDK 编解码或签名验证实现。

## 数据契约

手势数据、模型与实时推理始终使用 `ax,ay,az,gx,gy,gz` 的原始整数计数。校准诊断单独发出 g 和 °/s，不进入 `samples` 事件或训练流水线，以避免旧阈值/模型被不同单位污染。显示实际应用的校准组件，未应用校准不作精度保证。停止或断连清空实时诊断值。

订阅成功后的新批次才建立 IMU 就绪状态。新版固件无需切换手势模式；按键事件不能触发持续上报重启，否则会重置序号并打断手势。采样率与量程取设备报告，不静默重采样。

## 连接与操作所有权

Worker 同一时间只运行一次扫描或一个连接会话，连接期间界面不提供扫描。`scan_finished` 在扫描成功、失败、取消或被拒绝后都会发出，是界面结束加载状态的唯一依据。

每类数据流只有一个业务层消费者，而非整条连接共用一个串行消费者。固定 SDK 按命令分流，原始 IMU 与音频由同一 BLE 会话监督的独立任务并发消费；实时/远程录音、设置查询、历史或自动下载及保存均不得触发 IMU 停报、重订阅、丢弃样本或清空其队列，以保留序号连续性。音频操作之间仍串行，校准、诊断与 OTA 仍独占所需资源；音频尚未清理完成时不得启动维护。SDK 拥有分片写锁和同响应请求锁；应用不得在调用 SDK 发送前重复获取同一写锁。队列观察限于固定 SDK 的接入边界，局部 wire ID 不是另一份 SDK。

音频取消或文件/解码错误只结束音频操作，不改变 IMU 状态；真正的传输错误交由会话处理。断开或退出时取消并等待两条任务，音频 STOP/END 和完整文件保存只能收到一次取消请求，清理完成后才断开连接。

校准向导等待用户摆放时继续丢弃闲置 IMU，避免有界队列溢出。维护开始前等待在途电量查询，操作期间不再发电量请求。普通瞬时 IMU busy/timeout 不等同断连；真正链路丢失才退避重连，手动断开取消重试。

## 录音完整性

远程录音固定 FLASH，实时录音固定 LIVE_AND_FLASH；均使用断线 STOP，以保留设备副本并限制无人值守录音。START 超时查询状态，不重复 START；不能确定属于本次操作的 session 时不得误停其他录音。停止 ACK 不等于已保存，需等待终态确认。

实时 PCM 先订阅后开始，仅通过完整 END 校验后生成 WAV，取消/丢包的部分数据不报告为完整录音。保存通知后的下载失败必须报错，不能伪装成尚无新通知。原始下载文件先落盘，转换失败保留原始数据；唯一文件名避免覆盖。不做语音识别或自动删除设备录音。

实时接收提供默认关闭、开始前选择的本机播放选项，录音期间不可切换；远程 FLASH 录音不受影响。单一消费者将格式与顺序校验后的 PCM 分流到默认音频输出，监听不代表录音已完整。sounddevice/PortAudio 仅属于 Studio，延迟导入并在独立线程打开和清理，以免声卡操作阻塞 Tk/BLE。播放队列最多保留 500ms 音频；短暂缺帧补静音，积压或输出故障停止本次播放并警告一次，不改变接收数据或保存判定。正常结束、取消与断连均等待播放资源释放，不留下后台声音；不提供输出选择、音量调节或历史回放。

## 本机校准

加速度六面拟合后用新数据覆盖三个不同轴独立验证；陀螺仪先等待三个稳定窗口，再长时间静止采集并独立验证。沿用 SDK 质量门槛，全部要求通过且正常停报后才原子保存；取消、验证或存储失败保留旧配置。绑定设备标识、型号、完整固件和量程，不自动迁移不匹配配置。显式确认重置只删除 SDK 为当前设备生成的本机路径，也可清理损坏配置，不写戒指。

## OTA 信任与退出

信任锚由用户从独立可信来源提供，不接受固件包内自带密钥建立信任。离线验签展示签名元数据，二次确认后使用同一不可变字节快照；拒绝测试包与原始 BIN。SDK 在传输前复验签名和设备兼容性。

升级独占连接，包含预期的重启、重连和完整版本核验。传输 100% 不能报告成功；普通断连重试逻辑不得抢占 OTA 的重连。提交时立即锁定其他设备操作、普通退出与断开，等待 SDK 完成或超时。每次 OTA 尝试结束 Studio 会话而不自动重试，避免在安装结果不确定时再次刷写。

## Python 插件契约

插件仅进入新 Qt 界面；推理包不依赖插件或 Qt。清单声明 API 版本、入口、平台、设置、动作参数及事件。每个插件独立 Python 子进程和虚拟环境，但任意 Python 拥有当前账户权限，权限清单不是沙箱。首次启用、更新后重新运行、新增权限分别确认；默认不启动插件服务，不开启手势控制，不自动更新。关闭应用清理宿主启动的插件进程。

本地目录/ZIP 安装到托管目录，GitHub 下载固定 commit；拒绝归档越界、符号链接和过大文件。依赖仅用户显式安装，使用固定版本的 wheel，不在宿主环境安装或执行额外安装脚本。准备失败保留已安装版本和用户数据。设置和绑定原子保存；密钥仅系统凭据库或当前会话保存，不明文回退。

手势绑定使用模型内容指纹和用户手势名，可一手势多动作，每条独立启用、参数和冷却（默认 800ms）。每插件串行、跨插件并行，等待队列最多 20 条，满队列拒绝并记录；普通动作默认 30 秒，录音后处理默认 120 秒，超时终止该插件并清空队列，不自动重试外部副作用。配置保存后影响新任务，不改变在途任务。断连、更换模型、OTA 关闭手势控制，恢复后不自动开启。

录音与实时推理可复用同一 IMU 消费链路并行，训练采集与维护不因此放宽。SDK 录音操作经主线程状态检查，单一会话记录发起插件和 ID；插件不能停止其他发起者的会话，用户仍可停止。录音完成订阅默认关闭，启用后默认仅处理自身发起的录音；所有新录音及上传用途需明确确认，不回放历史事件。完整保存成功才发送 recording.completed，停止 ACK、进度 100%、取消和失败均不等价于完成。完成回调不得再次发起录音。禁用或卸载录音发起者先确认停止并保存；确认后重新检查状态。

插件仅默认获得当前事件必要信息，不自动暴露原始 IMU、录音历史或实时 PCM。官方接口的用途确认不约束绕过 SDK 的任意 Python，界面与文档必须明确这一信任边界。

## 验证边界

模拟传输与服务测试证明调用顺序、IMU/音频命令分流与持续消费、取消、文件完整性和互斥策略；不证明真实 BLE 并发吞吐、麦克风/音频输出效果与延迟、校准精度或固件安装。软件测试不得自动录音、校准实际设备或刷机。目标硬件仍需人工验收。
